## Definition of done

The four existing screens read as one product and provide an understandable route from an example or real pad to comparison, detailed inspection, saved work and a physical-test handoff. All internal navigation, primary actions and downloads are exercised on the running app. Cross-page case transfer preserves exact inputs and identifies assumptions. Navigation/back/reload must not silently destroy user drafts or attach old computed results to edited inputs. Existing solver, physical qualification labels, historical source-bound archives and lab releases remain intact. The app explains what a user can get today without promising manufacturing approval.

## Scope and verification

Four existing pages and their JS/CSS, one common navigation/presentation layer, minimal server routing for concrete resources or transfer only if needed. Reuse all physics and established formats. No new framework, product account system, cloud service or new physical model. Browser baseline precedes edits; two whole UX shapes are compared before committing. Root owns actual CUA browser sessions. Delegates inspect code and propose designs with disjoint report files. Rigor is behavioral flow coverage and authentic downloaded artifacts rather than a broad rewrite. Preserve the current user tab and work.

Acceptance covers consistent navigation and current-page state, visible purpose and next actions, board/example to editable case to fresh detailed solve, own-footprint pad study, saved draft restoration across navigation/reload, invalid/unsupported/failure states, current-result export invalidation, usable lab resources and all displayed internal links. Actual browser screenshots and receipts supplement focused automated route/format checks and the existing relevant suite.
