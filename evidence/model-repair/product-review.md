# Load-controlled product review

Independent review against `dccbcf6`, completed on 2026-10-16. The reviewer used the inherited model. This was not a review by a different model family. The review changed no product code.

No accepted product blocker remains in the reviewed load-controlled workflow. The physical evidence campaign and live browser qualification are separate work.

## Reviewed computation

The request is a height-free `LoadSpec`. Its immutable fields contain the prescribed downward normal load. The result preserves that request and records the solved `JointSpec` in `equilibrium`.

The native solve starts from a geometry-only spherical-volume seed. Height is an optimizing parameter with a downward-load energy term. Numerical qualification checks the native height, the moving rim, refinement, volume, and local Hessian. Native trial heights are unbounded. The accepted final height must satisfy the existing 0.02 to 10 mm input bounds.

A separate fixed-gap solve recomputes the upper-pad forces at the resulting height. The reported mesh and forces come from that solve. The load residual must satisfy the stated numerical tolerance. A native result with a sampled pad-plane excursion cannot qualify as a loaded result. Failed requests retain their input and evidence without a top-level solved height, mesh, or force.

## Findings and repairs

1. Replay assumed that a fresh solve always returned forces. A loaded failure returns a failed result instead of raising `SolverError`. Replay now reports that failure and exits 1 before it accesses forces or height. The focused regression confirms that replay passes a height-free `LoadSpec` back to the solver.
2. The browser still required nonzero offset for every comparison. The backend permits aligned loaded comparisons of solved heights. The browser condition now permits those comparisons. This repair was checked in source. The root agent owns the live browser check.
3. Successful loaded exports initially wrote empty standalone model, command, and log files. Their contents survived inside `evidence.json`. The exporter now puts the independent fixed-gap files at the case root and the native files under `load-height/`. A real archived solve confirms both groups contain the correct files.
4. The reader rejected a seven-row bundle generated by the exporter. Its uncompressed size was 128,521,163 bytes, above the old 120,000,000-byte cap. The reader now permits 160,000,000 uncompressed bytes. Its 40,000,000-byte compressed cap and 100-member cap remain. The same seven-row artifact now reads successfully.

## Direct checks

A fresh native control doubled both surface tension and normal load for the aligned 270 µm CSP case. The request used 0.96 N/m, 8 µN, no gravity, a 280 µm upper pad, and volume `0.01745 + pi*(0.27/2)^2*0.034` mm³. The result was numerically checked. Its solved gap was 0.22468060357009126 mm. The independent force residual was 0.0006515845996872827 µN. This agrees with the nominal 0.48 N/m, 4 µN gap to about 0.0001 µm. The request contained no height.

## Limits of this verdict

The native solve does not prove global uniqueness or constrain every intermediate trial height. Pad-plane checks inspect the exported tessellation. The model has no substrate obstacles, moving contact lines, package tilt, or load redistribution between joints. The export mesh does not carry a self-intersection proof.

These numerical checks do not establish material accuracy, a valid contact-pinning regime, or manufacturing readiness. The physical data, source assumptions, and practical design decision require the separate physical campaign.

The Prove It Works principle changed this review from inspection alone to an additional native control and an actual seven-row export round trip. Model the Domain focused the contract review on the distinct request and equilibrium types.
