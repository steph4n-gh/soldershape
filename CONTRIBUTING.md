# Contribute to SolderShape

Useful contributions improve a specific engineering comparison, correct a model or numerical defect, reproduce a physical discrepancy, or remove friction from the existing workflow. New physics and platforms need a bounded example and a decisive check before infrastructure.

Read the [model and validation status](docs/model-and-validation.md). Build the pinned engine and run the [development checks](docs/development.md). Keep changes narrow and preserve numerical thresholds, failed cases, third-party notices and historical evidence.

For a bug report, include the application commit, operating system, Python version, engine provenance, exact steps and the observed outcome. Use a minimal synthetic or shareable footprint and case. Do not upload proprietary boards, personal data or credentials. A numerical discrepancy needs the expected source, assumptions and raw receipts. Distinguish numerical agreement from physical measurement.

For a change, explain the user-visible problem, resulting behavior and verification performed. Update the relevant guide when commands or behavior change. Include actual downloaded evidence when an export or replay path changes. Screenshots help UI review, but they do not establish numerical or physical correctness.

Original contributions are offered under the repository's MIT license. Preserve separate third-party terms. Do not submit material you lack permission to distribute. This project currently has no promised response time or commercial support agreement.

The public repository and issue channel are pending release. [Launch readiness](launch/READINESS.md) records that status. Security-sensitive reports follow [SECURITY.md](SECURITY.md).
