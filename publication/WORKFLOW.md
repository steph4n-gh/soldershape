## Done predicate

The actual public GitHub repository belongs to the verified steph4n-gh account, receives this project without rewriting history, and has private vulnerability reporting enabled. Maintained onboarding and security instructions point to working public destinations. Hosted CI succeeds on the exact release commit. A research prerelease supplies the complete, manifest-checked package with required lab downloads and notices. The published static Site shows the same walkthrough, links to that release, and loads anonymously at soldershape.steph4n.dev. No hosted native solver or physical qualification is claimed.

## Throughput checkpoint

The work has four coupled units. Root owns GitHub repository and security configuration, publication metadata, exact-release CI and packaging, then Sites source synchronization and public deployment. The riskiest first checks are authenticated ownership, existing repository state, current Site identity and available public audience. There is no application rewrite or new hosting stack. Only a bounded independent source/comment review is delegated. Its report has a separate writable path. Root alone mutates the repository, release, Site mirror and publication receipts.

## Sequence

1. Create the empty public repository, configure its private reporting channel, and read back the settings before pushing source.
2. Replace pending-source instructions with verified repository, reporting and download destinations. Preserve historical evidence and bounded physics claims.
3. Review and run applicable checks, push the exact source, then observe hosted CI. Diagnose and fix an actual failure before release.
4. Build a complete candidate from the release commit, verify a fresh extraction and a native replay, attach the package and hashes to a clearly labeled prerelease, and verify actual release metadata and downloads.
5. Open the existing Site source repository with its helper, copy canonical static source, verify and save the exact pushed source, deploy it and set public access under the user's explicit launch authorization.
6. Verify anonymous HTTPS content, links, recorded controls, video and actual evidence downloads. Preserve receipts, stop temporary QA servers, and leave the user's existing workbench available.

## Representation and scope

The public app release commit, Site source commit, saved version, deployment and access policy are separate identities. Receipts retain those identities explicitly. The static page continues selecting the two immutable native scenarios. Numerical algorithms, source evidence and physical qualification remain unchanged.

Laziness Protocol keeps the existing workflow, native verifier and Sites project. Prove It Works requires readback of security settings, the exact hosted CI result, release assets, deployed bytes and anonymous browser behavior. User authorization on this turn includes the public repository and deployment, so no second permission gate is needed.
